================================================================
  BtP OVEN  -  TRAINING GUIDE
================================================================

Two different things happen in the training system:

  CAPTURE  (inside the plugin, instant)
      A button files the current audio into the right folder.

  TRAIN    (one-time Python script, GPU, 30-60+ min)
      A script reads those folders and produces a new model.

The plugin cannot run hours of GPU training inside the VST, but it
does all the sorting, naming and saving for you.  You press one
button, the audio lands in the correct place, and later you run one
command to learn from it.


----------------------------------------------------------------
0. GPU SETUP (ONE TIME, ONLY FOR TRAINING)
----------------------------------------------------------------

You do NOT need this to use the plugin.  Generation, stems, voices
and variants all work as installed.  This section is only for
TRAINING a new RVC voice with train_voice.py.

WHAT YOU NEED
  * An NVIDIA GPU (RTX 5070 / 40-series / 30-series).
  * The normal NVIDIA graphics driver.  You do NOT need the CUDA
    Toolkit, Visual Studio, or any extra CUDA installer: the torch
    wheel below already contains the CUDA runtime.
  * Python 3.10 - normally the one inside your RVC-WebUI install.
  * ~3.5 GB of free disk for the GPU build of torch.

STEP 1 - FIND YOUR PYTHON
  The trainer uses Python from your RVC-WebUI folder.  Default:

    D:\Dev\ai-gen-app\Retrieval-based-Voice-Conversion-WebUI

  If yours is somewhere else, tell the script once per terminal:

    set BTP_RVC_WEBUI=D:\your\path\Retrieval-based-Voice-Conversion-WebUI

  The Python executable is usually:
    <RVC-WebUI>\.venv\Scripts\python.exe
  or the Python 3.10 you already use for that WebUI.

STEP 2 - INSTALL THE GPU BUILD OF TORCH
  Open Command Prompt and run (replace the python path with yours):

    "D:\Dev\ai-gen-app\Retrieval-based-Voice-Conversion-WebUI\.venv\Scripts\python.exe" -m pip install --index-url https://download.pytorch.org/whl/cu130 "torch==2.11.0+cu130" "torchaudio==2.11.0+cu130"

  Notes:
    * This is the pair that was tested on an RTX 5070 (Blackwell,
      compute capability 12.0) with driver 617.x.
    * torch and torchaudio MUST be the same version.  Do not let pip
      pick two different versions.
    * cu128 works too (any recent torch 2.7+ cu128 wheel includes
      RTX 50-series support).  cu130 is simply the newer stack.
    * An older cu11x wheel may install but fail with "no kernel image
      is available for execution on the device".
    * This downloads a few GB.  It does not replace your driver.
    * If pip is missing, run:  python -m ensurepip --upgrade

STEP 3 - CHECK THAT CUDA IS SEEN
  Run:

    "D:\Dev\ai-gen-app\Retrieval-based-Voice-Conversion-WebUI\.venv\Scripts\python.exe" -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0)); print(torch.cuda.get_device_capability(0))"

  You want:
    * a version ending in +cu130 (or +cu128)
    * True
    * your GPU name
    * (12, 0) for an RTX 50-series card

  If it prints False, the CPU build is still installed.  Re-run
  STEP 2 in the SAME python you just tested.

STEP 4 - INSTALL THE EXPORT HELPERS
  The ONNX export needs onnx and onnxsim.  The trainer installs them
  automatically, but RVC's pinned numpy (1.23.5) needs matching
  versions, so if the automatic install fails run:

    "D:\Dev\ai-gen-app\Retrieval-based-Voice-Conversion-WebUI\.venv\Scripts\python.exe" -m pip install "onnx==1.14.1" "onnxsim==0.4.36" "numpy==1.23.5"

  (onnx 1.16+ pulls numpy 2, which breaks RVC's numba 0.56.4.)

STEP 5 - RUN THE TRAINER
  See section 3 below.  If CUDA is working you do not need any
  special flag.  The script prints:

    [train] torch : 2.11.0+cu130   cuda: True

  If you only have CPU torch and still want to try, add --allow-cpu.
  It works, but 200 epochs can take many hours instead of ~30-60 min.

TROUBLESHOOTING
  "torch has no CUDA device"
      STEP 2 was run in a different python than the one running
      train_voice.py.  Check the [train] torch line it prints.

  "CUDA out of memory"
      Lower --batch-size (try 4 or 2), or close other GPU apps.
      The plugin's generation models also use VRAM - close the DAW
      while training if you are tight on memory.

  "no kernel image is available"
      Wrong CUDA wheel for a 50-series card.  Install cu128 or newer.

  "No Python at ..."
      A stale virtual environment.  Recreate it, or point
      BTP_RVC_WEBUI at a working RVC-WebUI install.

  "No module named onnxscript"
      Harmless.  The trainer already forces torch's legacy ONNX
      exporter, which does not need onnxscript.

  Training stops with a Windows access-violation error
      This was a bug in RVC's single-GPU path (it always wrapped the
      networks in DistributedDataParallel).  The shipped trainer
      already works around it; update Tools\train_voice.py if you
      are running an older copy.

  Missing parselmouth / soundfile / onnx / onnxsim
      The trainer installs them automatically into
      %APPDATA%\BtP Oven\Training\pydeps on the first real run.


----------------------------------------------------------------
1. WHERE EVERYTHING GOES
----------------------------------------------------------------

All captures land under:

  %APPDATA%\BtP Oven\Training\

  Training\
    Vocals\                 RVC voice training + vocal takes
    Loops\                  full loops for ACE-Step / RAVE
    Variants\               RAVE mutations
    OneShots\
      FX\
      Impacts\
      Risers\
      Pads\
      Vocal Chops\
      Sirens\
      Phones\
      Cash\
      Ambience\
      Synth One Shots\
    Stems\
      drums\  bass\  other\  vocals\
    runs\                   training work folders (script output)
    manifests\              example JSON files (this guide)

Which button writes where:

  PAGE     BUTTON        FOLDER
  ----------------------------------------------------------
  VOICE    TRAIN & SAVE  Training\Vocals
  AI GEN   TRAIN         Training\Loops
                          (Training\Vocals if the take was sung,
                           or the selected loop when there is no take)
  SHOTS    TRAIN         Training\OneShots\<selected category>
  SHOTS    TRAIN VAR     Training\Variants
  STEM     TRAIN (row)   Training\Stems\<drums|bass|other|vocals>

File names are automatic:
  <slug of your prompt>_<timestamp>.wav
so nothing overwrites anything.  The status line shows the full path
after every capture.


----------------------------------------------------------------
2. WHAT AUDIO TO CAPTURE
----------------------------------------------------------------

RVC VOICE (Training\Vocals)
  * ONE consistent voice, nothing else.
  * 10-60 minutes total is ideal.  10 min minimum.
  * Dry: no reverb, no delay, no music bed.
  * Consistent mic/room.  Do not mix 5 different microphones.
  * Singing AND speaking are both fine; keep the style consistent.
  * Formats accepted: wav, mp3, ogg, flac.
  * Tip: use the STEM page to strip vocals from a song first,
    then TRAIN the vocal stem.

ACE-Step LOOPS (Training\Loops)
  * Complete musical loops, 4-30 seconds.
  * One tempo / key per training set is best.
  * Royalty-free or your own audio only.

RAVE VARIANTS (Training\Variants)
  * These are the mutated outputs.  Capturing them builds a set of
    "in-between" timbres for a future custom RAVE model.

ONE-SHOTS (Training\OneShots\<category>)
  * Short single hits: 0.2-4 seconds.
  * Put the right sound in the right category.  The category you
    select in the SHOTS page is the folder it writes to.

STEMS (Training\Stems\<type>)
  * Isolated drums / bass / other / vocals from the STEM page.
  * Great as source material and for future stem models.


----------------------------------------------------------------
3. TRAINING AN RVC VOICE
----------------------------------------------------------------

The script is in Tools\train_voice.py (also in the project root as
train_voice.py).

WHAT YOU NEED
  * A GPU (RTX 5070 is great).
  * The RVC-WebUI install that ships with this toolchain, normally:
      D:\Dev\ai-gen-app\Retrieval-based-Voice-Conversion-WebUI
    (point BTP_RVC_WEBUI at it if it lives somewhere else.)
  * Python 3.10 with the RVC dependencies (the script adds the paths).
  * The GPU build of torch - see section 0 for the exact commands.

STEP BY STEP
  1. Capture 10+ minutes of one voice with VOICE -> TRAIN & SAVE.
     They appear in %APPDATA%\BtP Oven\Training\Vocals.

  2. Open a terminal and run:

       python Tools\train_voice.py --name "my_rnb_male"

     Optional flags:
       --input "D:\my\voice\folder"   use a different folder
       --epochs 200                   training length / quality
       --sr 40000                     RVC v2 sample rate
       --batch-size 8                 lower this if VRAM runs out
       --dry-run                      check setup without training
       --allow-cpu                    train without CUDA (very slow)

  3. The script preprocesses, extracts pitch + features, trains, and
     exports an ONNX voice.  Expect 30-60+ minutes.

  4. The finished file lands in:

       %APPDATA%\BtP Oven\Models\RVC\voices\my_rnb_male.onnx
       (or D:\Dev\rvc-models\voices\ on the dev machine)

  5. Reopen the VOICE page (or restart the plugin) and pick the new
     voice from the dropdown.

TIPS
  * If you have very little audio, lower epochs.  Quality drops.
  * If the voice sounds unstable, add more clean audio before
    changing settings.
  * If training errors on a missing package, install that package
    into the same Python environment and rerun.


----------------------------------------------------------------
4. TRAINING / EXPORTING RAVE (ADVANCED)
----------------------------------------------------------------

The plugin uses two ONNX files plus a filter bank:
  Models\RAVE\rave_encoder.onnx
  Models\RAVE\rave_decoder.onnx
  Models\RAVE\pqmf_hk.bin

These were exported from the RAVE "voice_multi" checkpoint, published
by the Intelligent Instruments Lab:

  https://huggingface.co/Intelligent-Instruments-Lab/rave-models
  checkpoints/voice_multi_b2048_r48000/config.gin
  checkpoints/voice_multi_b2048_r48000/version_0/checkpoints/last.ckpt

  Licence: CC-BY-NC 4.0
  Cite:    Intelligent Instruments Lab. rave-models. 2023.
           doi:10.57967/hf/1235

Because those weights are non-commercial, the SHOTS -> MUTATE row is
compiled out of the commercial build. If your copy of the plugin has
no MUTATE button, this whole section is informational only - the
plugin was built with -DBTP_ENABLE_RAVE=OFF and contains no RAVE
code or models. See BUILD-VARIANTS.txt for both build flavours and
how to put RAVE back into a personal build.

To build a new RAVE model from your own audio you need the training
toolchain (acids-rave + a RAVE fork), which is a heavy GPU job.

The export helper is in Tools\rave_export.py.  It expects:
  * a RAVE .ckpt checkpoint
  * the matching config.gin
  * Python with torch + gin-config + cached_conv

Example:
  python Tools\rave_export.py ^
      --checkpoint D:\rave\my_model.ckpt ^
      --config D:\rave\my_model\config.gin ^
      --out "%APPDATA%\BtP Oven\Models\RAVE"

It writes rave_encoder.onnx, rave_decoder.onnx and pqmf_hk.bin.

NOTE: the export intentionally skips the decoder's FFT noise module
so the graph fits in ONNX.  That is why variants are slightly
"cleaner" than a native RAVE render.  Timbre mutation still works.


----------------------------------------------------------------
5. ACE-STEP LORA - REAL FINE-TUNING
----------------------------------------------------------------

This is the part that lets you train your OWN sound into the AI.
The plugin captures the dataset, runs a one-time GPU job, and then
loads the resulting adapter in-process like any other LoRA.

WHAT YOU NEED (one time)
  * NVIDIA GPU.  12 GB works for loop-length captures (tested on an
    RTX 5070: 4.6 GB peak, ~20-60 s per run).
  * ACE-Step 1.5 installed somewhere, with its checkpoints:
      <ACE-Step-1.5>\train.py
      <ACE-Step-1.5>\checkpoints\acestep-v15-turbo
      <ACE-Step-1.5>\checkpoints\vae
      <ACE-Step-1.5>\checkpoints\Qwen3-Embedding-0.6B
  * A Python environment with the ACE-Step requirements.  Reuse the
    one that ships with ACE-Step:
      <ACE-Step-1.5>\.venv\Scripts\python.exe
    To build a fresh one (Python 3.11 or 3.12):
      cd <ACE-Step-1.5>
      py -3.12 -m venv .venv
      .venv\Scripts\python.exe -m pip install --upgrade pip
      .venv\Scripts\python.exe -m pip install -r requirements.txt
      .venv\Scripts\python.exe -m pip install -r requirements-sidestep.txt
    The plugin only needs to find python.exe and train.py.

POINT THE PLUGIN AT IT
  The trainer auto-detects these locations:
      D:\Dev\ACE-Step-1.5
      %APPDATA%\BtP Oven\ACE-Step-1.5
      <plugin folder>\ACE-Step-1.5
  If yours is elsewhere, create this file once:
      %APPDATA%\BtP Oven\lora_settings.json

    {
      "acestep_root": "D:\\your\\ACE-Step-1.5",
      "python": "D:\\your\\ACE-Step-1.5\\.venv\\Scripts\\python.exe"
    }

  Environment variables also work for one session:
      set BTP_ACESTEP_ROOT=D:\your\ACE-Step-1.5
      set BTP_LORA_PYTHON=D:\your\ACE-Step-1.5\.venv\Scripts\python.exe

TRAIN IT
  1. Capture audio with the TRAIN buttons (Loops, Vocals, One-shots,
     Variants or Stems).  Every capture also writes a .json sidecar
     with its prompt/caption, lyrics, BPM and key, so the trainer
     knows what the audio is.
  2. On AI GEN, press TRAIN LORA.
  3. Pick the data folder (usually Loops), epochs and rank.
       rank 8-16   good default for 12 GB cards
       rank 32     larger datasets / more capacity
       epochs 40   first try; 100+ for a strong style
     The dialog shows how many files are in the folder.
  4. A console opens and shows preprocessing, training and export.
     Logs also land in Training\runs\lora_<name>.bat.
  5. When adapter_model.safetensors appears, the plugin selects and
     applies the new LoRA automatically.  Press GENERATE.

DATASET GUIDANCE
  * 30-120 loops of the same style / tempo family gives a clear
    style LoRA.  Fewer files still work but move the sound less.
  * Clean intros, no long silence.
  * Consistent BPM and key where possible.
  * Vocals: the LoRA trains the instrumental/style model, not the
    4B lyric singer.  Vocal TIMBRE still comes from RVC voices.
  * Do not mix unrelated genres in one LoRA; train one character.

FILES AND MANUAL USE
  Output: %APPDATA%\BtP Oven\LoRAs\<name>\
      adapter_model.safetensors
      adapter_config.json      (alpha is read automatically)
      lora_info.json           (dataset / epochs / rank record)

  The same job can be run by hand:
    "%APPDATA%\BtP Oven\Tools\train_lora.py" --name my_sound ^
      --audio-dir "%APPDATA%\BtP Oven\Training\Loops" ^
      --epochs 60 --rank 16

  Work files live under <ACE-Step-1.5>\_btp_lora\<name>\ because the
  official trainer sandboxes paths to its own folder.  They are safe
  to delete after training.

LORA PICKER
  Discovery runs on AI-page open, after TRAIN, and when LORA DIR is
  pressed.  It scans:
    %APPDATA%\BtP Oven\LoRAs\<folder>\        adapter folders (preferred)
    %APPDATA%\BtP Oven\LoRAs\*.safetensors    loose files
    <ACE-Step model folder>\                  optional second location
  Select one, set SCALE, press APPLY, then GENERATE.  SCALE 0 = off,
  1.0 = trained strength, above 1 pushes the style harder.


----------------------------------------------------------------
6. THE EXAMPLE JSON MANIFESTS
----------------------------------------------------------------

The manifests\ folder contains one editable JSON file per AI job.
They document the settings and the folders.  You can edit them for
your own notes, or use them as a machine-readable recipe if you add
automation later.

  manifests\ace_step_track.json    instrumental loop generation
  manifests\ace_step_vocals.json   lyrics + sung vocals
  manifests\one_shot.json          one-shot generation by category
  manifests\stems.json             Demucs stem separation
  manifests\rvc_voice.json         RVC voice training
  manifests\rave_variant.json      RAVE latent mutation
  manifests\master.json            15 ready presets (R&B / dark trap)

master.json is different from the other manifests: the AI GEN page reads
it at startup and fills the PRESET picker.  It covers tracks, loops and
vocals for R&B and dark trap.  Add your own entries to the "presets"
array (id, category, style, name, bpm, duration, steps, guidance, seed,
prompt, lyrics, with_vocals) and reopen the AI page.  A copy in
%APPDATA%\BtP Oven\Training\manifests\master.json overrides the bundled
one.

MINIMAL EXAMPLE (rvc_voice.json):

  {
    "ai": "rvc",
    "kind": "voice",
    "voice_name": "my_rnb_male",
    "capture_folder": "%APPDATA%\\BtP Oven\\Training\\Vocals",
    "output_model": "%APPDATA%\\BtP Oven\\Models\\RVC\\voices\\my_rnb_male.onnx",
    "settings": {
      "sample_rate": 40000,
      "epochs": 200,
      "batch_size": 8,
      "f0_method": "rmvpe"
    },
    "source_audio": {
      "formats": ["wav", "mp3", "ogg", "flac"],
      "min_minutes": 10,
      "one_speaker": true,
      "dry_no_reverb": true
    }
  }

MINIMAL EXAMPLE (ace_step_track.json):

  {
    "ai": "ace_step",
    "kind": "track",
    "name": "dark_trap_140",
    "capture_folder": "%APPDATA%\\BtP Oven\\Training\\Loops",
    "settings": {
      "sample_rate": 48000,
      "channels": 2,
      "bpm": 140,
      "bars": 8,
      "loop": true,
      "normalize": true
    },
    "tags": ["trap", "dark", "808"]
  }

The plugin itself does not require these files to run.  They are
documentation + recipes so you always know where audio belongs.

7. LEGAL / ETHICS
----------------------------------------------------------------

  * Train only on audio you own or that is explicitly royalty-free.
  * Do not clone a person's voice without permission.
  * Do not redistribute a voice model you do not have rights to.
  * RAVE "voice_multi" weights are CC-BY-NC 4.0. Credit the
    Intelligent Instruments Lab and cite doi:10.57967/hf/1235 when
    you use them.
  * Selling music made with a RAVE variant is permitted by the model
    authors - they draw the line at selling the models themselves as
    part of a product. Shipping the models inside a paid plugin is
    what is not allowed. See LICENSING.txt.
  * Selling the plugin itself is only allowed for a build compiled
    without RAVE (-DBTP_ENABLE_RAVE=OFF). See BUILD-VARIANTS.txt.

If you are unsure about a sample, do not put it in a training
folder.  Keep a "reference" folder outside Training\ for things you
only listen to.
